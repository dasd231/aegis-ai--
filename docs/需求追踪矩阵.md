# Question.md 需求追踪矩阵

本表以仓库根目录 `Question.md` 为唯一验收基线。状态含义：**完成**＝代码、接口/界面与验证证据齐全；**设计完成**＝题目明确“不要求完整代码”的设计项；**有意限定**＝已实现用户追加目标的一部分且清楚说明边界，不虚报全能力。

## 1. 必做功能

| 原始需求 | 状态 | 实现证据 | 验证证据 |
|---|---|---|---|
| 邮箱或手机号 + 密码注册/登录 | 完成 | `api/auth.py`、Argon2、JWT issuer/audience；`/user` 与 `/admin` 双入口、浏览器登录态隔离 | `test_auth_sessions.py`、双入口 HTTP 200 与双角色在线验证 |

| 回答点赞/踩和文字反馈 | 完成 | `api/feedback.py`、`feedback` 唯一约束、回答内可选文字反馈编辑器 | 新增/更新/越权测试、前端构建 |
| TXT/MD/PDF 上传、解析、向量化 | 完成 | `api/knowledge.py`、multimodal/parser/chunking/vector_store | 真实上传→ready→检索测试 |

| 空检索标准兜底、不编造 | 完成 | 不调用 LLM，固定 fallback、中文双字词置信门、正常未知问题建议人工 | 空库 SSE、品牌近邻误召回反例、30 条困难黄金集 |
| 每用户每天最多 100 次可配置 | 完成 | DailyUsage 唯一键 + 条件 UPDATE 原子扣减，业务时区 | 并发安全逻辑与 API 测试 |

| 后端完成向量/LLM 调用 | 完成 | API Key 仅后端环境变量，前端无模型 SDK | 源码与依赖审计 |
| LLM 超时/限流异常处理 | 完成 | 有界重试、指数退避、bulkhead、circuit breaker、安全摘录降级 | resilience/rag 测试与 capacity 端点 |

| 启动后可直接测试 | 完成 | 首次只配置不入库的 `.env`；后续一条 `docker compose up --build -d` 自动启动三层服务、升级 Alembic、创建管理员并向量化三篇受管资料；默认 mock/local_hash 无需 API Key | Compose 三服务 healthy、双入口与小米客服矩阵 |

| 长短对话与任务记忆 | 完成 | 最近轮次、显式同意的抽取式摘要、结构化 slots + 乐观锁 |

## 5. 最终质量门

# 数据安全与合规治理

## 1. 数据分类与最小化

| 数据 | 当前处理 | 生产要求 |
|---|---|---|
| 密码 | 仅 Argon2 哈希 | 参数定期复核，禁止日志记录 |
| LLM/百炼密钥 | Fernet 加密密文 + HMAC 指纹，API 永不回显 | 主密钥放 KMS/Vault，轮换与双人审批 |
| 问题/回答 | MySQL 保存以满足历史会话 | 明确合法基础、地区和留存期，按租户加密/删除 |
| 引用快照 | 保存文档名、摘要和分数 | 纳入数据主体删除与法律保全流程 |
| 运行日志 | 只记录 ID、版本、耗时、状态 | 禁止 Authorization、Key、密码和未经批准的原文 |
| 反馈优化集 | 导出时规则脱敏，默认不可训练 | 人工复核、访问审批、用途和到期删除 |

用户原文可能主动包含隐私信息，应用功能库仍会保存它以支持历史会话；这不是“已完全脱敏”。生产必须按适用法律和组织制度确定告知同意、访问主体、保留期限、删除/导出 SLA、跨境与第三方模型的数据处理协议。

## 2. 访问控制与审计

- 普通用户资源查询始终绑定当前 `user_id`，越权统一返回 404；管理员接口二次读取数据库角色。
- 查看全量会话列表和会话详情会追加 `admin_data_access_audits`，记录管理员、目标、Request ID、业务用途和时间；应用没有修改/删除审计的 API。
- Provider 密钥变更与实验灰度变更分别保存版本前后快照和操作者；密钥审计只记录字段名与不可逆指纹。
- 数据库只追加表仍不能抵抗 DBA 或云账号直接篡改。生产应把审计流同步到受限 SIEM/WORM/对象锁存储，设置独立审计角色、校验哈希链或平台完整性证明，并定期做缺口检测。

## 3. 输出合规边界

Stable 与 Canary Prompt 均要求：只依据本轮 Evidence；逐事实引用；资料不足则拒答；不得承诺未授权的退款、赔偿、资格或状态；不得冒充品牌官方；不得输出系统提示、凭据、隐私与内部评分；不得索取或复述密码、验证码、完整证件号、银行卡号、API Key；一般客服信息不得包装成法律、医疗或财务专业结论。

Prompt 只是一个控制层。确定性输入护栏、产品/业务实体一致性门、关键规则保席、逐段 Claim Verifier（引用、数字、实体、危险动作极性与支持片段）、抽取式降级、人工接管和版本审计共同组成防线。涉及人身安全时只输出证据支持的紧急操作并建议使用官方/人工渠道。

## 4. 留存与删除建议

部署方应建立可配置的数据生命周期作业，至少分别管理：会话消息、反馈、上传原件、Qdrant chunk、引用快照、画像/记忆、运行日志、审计日志和脱敏训练集。删除流程需有幂等任务、重试、对账和法律保全例外；“删除向量”不等于删除 MySQL 引用、备份或第三方模型侧数据。

建议将普通会话、投诉争议、审计证据和优化数据设为不同策略，并记录 policy version。备份到期同样要清理；恢复演练后必须重放删除墓碑，避免已删除数据因旧备份恢复而复活。

## 5. 上线合规门

1. 完成适用地区的隐私影响评估、第三方模型 DPA、数据地域与训练用途确认；
2. KMS/Vault 管理主密钥，数据库、对象存储、Qdrant 传输和静态加密；
3. 管理员最小权限、MFA、临时授权和数据访问原因；
4. SIEM/WORM 审计、告警和定期复核；
5. AV/CDR 或隔离沙箱处理公网 PDF/图片；
6. 删除、导出、纠错、撤回记忆和安全事件响应演练；
7. 真实标注集上的引用支持率、拒答和高风险输出复核通过。

以上制度项不能仅靠代码宣称“合规”。项目提供的是可落实这些制度的技术控制点与审计证据，不替代法务判断。
